# DA4 adapter: レビュー対応後のv2 / v3再測定

2026年9月14日にv2・v3を両方再測定しました。v2は54条件×時間・メモリ＝108測定、v3は81条件×時間・メモリ＝162測定、合計270測定です。
過去の測定値は比較表に流用していません。DA4 API・ネットワーク通信・求解は使用していません。

## 測定条件

- v2: `4cff76ba3dd7df235759832918754a06e27efde2`、OMMX 2.6.1、2026-09-14 10:52:22〜10:53:26 JST。
- v2のAdapterインストール情報: `0.1.2.dev5+g4cff76ba3.d20260914`。測定前に各ブランチから再インストール済み。
- v3: `e578bbf9324b2b64a770e310fa7745d2e83c02ef`、OMMX 3.0.0b5、2026-09-14 10:58:50〜10:59:36 JST。
- v3のAdapterインストール情報: `0.1.2.dev61+ge578bbf93.d20260914`。測定前に各ブランチから再インストール済み。
- v3は`update_ommx_v3`の`d31504c`までを取り込み済み。前回のdecode修正に加え、`ABSOLUTE_TOLERANCE`によるペナルティ係数の比較、OneHot開始位置を固定するゼロ係数項の重複防止、エラーメッセージ・テストコメントの修正を含みます。
- 両ブランチに既存の`benchmarks/README.md`変更と過去の未追跡測定結果があります。測定対象の実装・測定コードに未コミット変更はありません。
- 環境: macOS-15.7.9-arm64-arm-64bit、論理CPU 8、Python 3.12.10、Pydantic 2.13.4、memray 1.20.0。全依存とlockfile SHA256は各metadata.jsonに記録。
- seed 0。合成レスポンスは実行可能状態1種類・frequency 16。16種類の解ではありません。全変数をconfigurationに含め、生成時にOMMXで実行可能性と変数ID対応を検証します。
- Knapsackの合成解は従来と同じ全0です。制約を満たしますが最適化した解ではありません。今回の比較では解の生成方法を変更していません。energy・求解時間などは合成値です。
- 時間の単位はms。初回と、warmup 3回後の20回の中央値を掲載。計測区間のGCは停止。
- メモリの単位はKiB。memrayで初回・2回目の追跡対象アロケーションのピークを測定。RSSではありません。メモリの2回目は時間測定のwarmup条件とは異なります。
- v2の時間→メモリ、v3の時間→メモリの順に直列実行。各ケース・測定種別は別プロセスを使用し、測定を並列実行していません。
- Instance生成、コピー、Policy生成、合成レスポンス生成・実行可能性検証は測定外。Preparationも単体測定以外では測定外。
- 表中のModelはDA4へ渡すQuboRequest、Resultは合成QuboResponseです。初回はセットアップ後の最初の対象操作を表します。
- Cliqueは等式の2乗後に4次項が残りv3で拒否されるため、v2・v3とも今回の測定から除外しました。v2の既存runnerに対し、実行時だけCliqueのケースを除外しています。
- v2のIndicator/SOS1比較用問題は、v3でloweringした後と同じ通常制約を直接生成しています。v2にPreparation単体の測定はありません。
- 比較率は丸め前の値で`(変更後 / 変更前 - 1) * 100`を計算。小さい差や初回値は初期化・計測ノイズの影響を受けます。
- v2/v3の差にはOMMXとAdapter実装、依存構成の差が含まれます。今回のレビュー対応だけの影響を切り分けた測定ではありません。
